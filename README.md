# zcode-tempo

为 AI 编程工作台显示模型生成速率。三击空格可以增强草稿，也可以在空输入框采纳预先生成的下一条消息。当前支持 Windows ZCode 4.0.0。

## 安装

若已安装 ByteRax ZCodeBox，先在 ZCode 中执行原版的 `/uninstall-overlay` 移除状态栏，再从「设置 → 插件」卸载原版。安装器会检查原版的状态栏加载入口和插件安装记录。

安装前完全退出 ZCode。需要 Python 3。在下载的源码目录运行以下命令，把示例路径换成包含 `ZCode.exe` 的实际目录。也可以让能访问本机文件和终端的 Codex 代为查找安装位置并运行命令。

```powershell
python -X utf8 scripts/install.py install --app-dir 'C:\Path\To\ZCode'
```

重新打开 ZCode 后生效。可以用相同的目录参数查看安装状态或卸载。同一个安装目录一次只执行一个操作。客户端升级后，先确认支持版本再重新检查。

```powershell
python -X utf8 scripts/install.py check --app-dir 'C:\Path\To\ZCode'
python -X utf8 scripts/install.py remove --app-dir 'C:\Path\To\ZCode'
```

安装只向 `app.asar` 的桌面入口增加本扩展的加载语句，并将运行文件放在相邻的 `resources/harness-zcode` 下。卸载移除本扩展的加载语句和运行文件。

## 使用

- 输入框工具栏在上下文图标和模型选择左侧显示 `xx tok/s`。生成中按文本增量更新。等待工具、审批或输出暂停时保留本轮最后的读数，恢复输出后继续更新。
- 完成或停止后，无工具的回合在宿主首末计时能覆盖本轮用量时，按每次请求从首个到末个内容增量的时间加权计算均速，排除首包等待和末次输出后的等待。遇到工具调用、未流出的推理用量、明显的输出中断或计时不足时，按本轮已观察到的输出增量估算，跳过已知的工具边界和长时间无输出的间隔。切换会话后仍累计同一轮已经采到的内容。采样不足时可显示本轮最后一次估算或已计时请求的均速。若只有回合工时，则使用本轮或本会话最近的可用统计（包括尚未加载的历史），并在悬停提示中标明含等待。
- **有草稿时增强。** 把光标放在末尾，在 700 毫秒内独立按下三次空格。当前模型会收到草稿与改写指令。若上一轮成功完成、为同一会话且供应商一致，改写请求还可带最多 1,200 字符的最终回复原文。长回复有可唯一定位的编号、标题或路径时才选取相应段落。模型不可用时需要重新选择，超时后可再试。
- 触发后，输入框工具栏附近会显示「正在增强…」。提示跟随原草稿，回填后消失。若模型返回原文，「增强完成，草稿未改动」会短暂显示约 1.5 秒。失败或超时会提示草稿已保留。
- **空框时预览和采纳下一条消息。** 当前前台会话成功回复后，若同一轮的输入框为空、输入框和模型已就绪且符合来源条件，就会发起预测。候选就绪后显示为输入框内的灰字，三击空格将它变成可编辑草稿。开始输入时隐藏灰字，尚无候选时空格照常输入。每轮最多调用当前供应商一次，输入为上一轮用户消息和最终回复的限长节选，请求计入供应商用量。会话、来源轮次或供应商切换后重新判断候选归属。
- 改写只回填发起增强的草稿。切走时，回到原草稿后再回填，其他草稿仍可单独增强。最多同时保留 64 个在途或待回填任务。队列已满时会提示，等任务结束或收下之前的结果后可再试。模型原样返回时保留等待期间新增的文字。采纳或回填结果可继续编辑，`Ctrl+Z` 恢复回填前的内容，消息由你发送。
- 增强保留用户授权的动作和交付范围，按排查、修改、方案等任务调整改写幅度。回填前会检查可识别的命令、代码块、路径和链接。发现关键内容被改动时，保留当前草稿并沿用原有失败提示。
- 草稿包含结构化 `@` 引用或附件时，保留原稿并提示暂不支持。当前首版验证范围为本地 Windows 会话。

## 实测

桌面回归使用 Windows ZCode 4.0.0 隔离副本与本地模拟模型服务，覆盖速率位置、首尾等待、工具调用前后更新、结束回退、三击增强及其提示、窄窗和浮动输入框、上下文发送、空框采纳预测、真实窗口最小化和恢复、跨草稿隔离和原生 `Ctrl+Z`。确定性测速测试覆盖工具跨帧完成、窗口晚刷新、同轮切换会话和末批输出合并提交。安装回归覆盖重复安装、原版冲突拦截、安装和卸载并发，以及卸载后安装包逐字节恢复。

Node.js 单测使用 `node --test tests/*.test.cjs`。Windows 安装器测试使用 `python -B -X utf8 -m unittest discover -s tests -p test_install.py`。

改写质量使用实际 `GLM-5.3-Flash` 做了合成样本对照。 [增强对照结果](docs/prompt-enhancement-comparison.md) · [上下文增强与预测实测](docs/context-enhancement-comparison.md)

复现时，将一份干净的 ZCode 4.0.0 安装目录复制到 `%TEMP%\harness-zcode-4-e2e\app`，对副本运行 `install.py install`。测试需要 Node.js 22 或更新版本。运行 `node tests/zcode-fixture.cjs`，等它输出 `debugPort`。在另一终端执行 `node tests/zcode-desktop.cjs <debugPort>`。夹具会禁用临时副本的系统打开方式注册，并调整启动时的遥测等待和预装工具准备。
